# 原型头脑风暴

通过自然协作把 PM 的原型想法变成可生成的页面设计。

<HARD-GATE>
在展示页面设计并获得 PM 批准之前，不要生成任何页面、不要写任何 pages/ 文件。实现阶段只能通过 zpm-new-page / zpm-new-page-tpl 命令生成。
</HARD-GATE>

## 流程

1. **探索上下文**：读 zpm.config.yaml（可用表）、/api/_meta（真实字段）、templates/ 五个模板、AGENTS.md；查 knowledge/assets/ 是否有可复用资产、knowledge/lessons/ 是否有相关经验
2. **澄清问题**（每次只问一个，尽量选择题）：
   - 页面目的：给谁看、回答什么问题
   - 页面类型：列表 / 表单 / 详情 / 仪表盘 / 看板 / 组合
   - 数据字段：展示哪些字段、什么枚举、如何过滤
   - 交互动作：增删改查、拖拽、导出、跳转
3. **提出方案**：推荐 1 个模板 + 布局分区描述 + 涉及的表与字段；给出理由与备选
4. **分节展示设计**：布局分区 → 字段与交互 → 数据来源。每节确认后再下一节；有分歧回退澄清
5. **批准后进入实现**：
   - 调用 zpm-new-page-tpl <模板> <需求描述>（模板明确时）或 zpm-new-page <需求描述>
   - 生成后立即调用 zpm-page-review 自查并修复阻塞项
6. **视觉确认循环**：让 PM 刷新浏览器看真实页面，收集修改意见 → 回到步骤 3 迭代（原型即 mock，不需要截图模拟）
7. **收尾沉淀提示**：PM 认可后，提示可以 zpm-asset-save 沉淀该页面为资产、zpm-lesson-save 记录本次经验

## 原则

- 一次一问；选择题优先；不堆砌问题
- 页面设计只描述分区与交互，不写代码——代码是 zpm-new-page 的事
- YAGNI：拒绝 PM 提出的「顺手加上」的非必要功能，提示可以后续迭代
- 数据字段必须落到真实表（/api/_meta），表不在 sync.tables 时先提示加配置 + zpm sync
