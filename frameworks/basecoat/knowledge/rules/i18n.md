# i18n 国际化（UI 文案 + 数据库翻译列）

宪法依据：PROP-20261108-01（v1.4.0 成文、v1.5.0 扩展）；与宪法冲突时以宪法为准。

## 适用范围

两层职责，模块分开，勿混用：

| 层 | 模块 | 数据来源 | 典型内容 |
|---|---|---|---|
| UI 文案 | `pages/i18n.js` 的 `t()` | `locales/<locale>.json` | 菜单、header、KPI 标签、空态/失败提示、图表图例等界面自有文字 |
| 数据库翻译列 | `pages/app.js` 的 `i18nText()` | 接口返回的 JSON 多语言字段 | 产品名、类别名等同步库的多语言列 |

## 1. UI 文案（locales/ 机制）

- **locale 文件**：`pages/locales/<locale>.json`（`zh_CN.json` / `en_US.json`，扁平 key）。zpm serve 把 `pages/` 映射到站点根，故 URL 为 `/locales/<locale>.json`；**不要放项目根 `locales/`**（根目录不被托管，fetch 会拿到 HTML 兜底页，2026-11-08 实测踩坑）
- **语言状态**：localStorage `langMode`（`zh-CN` 缺省 / `en-US`，可扩展），由外壳 header 语言切换下拉写入，切换后整页刷新生效；`<html lang>` 由外壳同步
- **加载器**（`pages/i18n.js`）：
  - `ensureI18n()`：幂等；`zh_CN.json` 恒为基础表，当前语言表覆盖基础表 → **en_US.json 缺 key 自动回退中文**，页面无需自行回退
  - `t(key, fallback)`：locale 表 → 调用点中文缺省（fallback）→ key 本身；**推荐调用点显式传中文缺省**（locale 文件加载失败时 fail-open，外壳仍全中文可用）
  - 外壳 `mountLayout()` 内部先 `ensureI18n()` 再构建；页面在渲染 UI 文案前自行 `await ensureI18n()`（与数据拉取并行亦可）
- **页面接入步骤**（静态标记两步走）：
  1. 静态 HTML 节点加 `data-i18n="<key>"`（节点内中文即缺省文案），JS 里 `for (const node of document.querySelectorAll('[data-i18n]')) node.textContent = t(node.dataset.i18n, node.textContent.trim())`；`document.title` 与 aria 属性在 JS 里单独 `t()` 赋值
  2. JS 动态文案直接 `t(key, 中文缺省)`；新 key 同步补进 `locales/` 全部语言文件
- **新增语言步骤**：`locales/` 加 `<locale>.json` → `i18n.js` 的 `LOCALE_FILES` 登记 → 外壳语言下拉 `options` 加一项。三项缺一不可

## 2. 数据库翻译列（i18nText）

- 同步库的多语言字段以 JSON 串形态存储（如 `{"en_US":"Large Cabinet","zh_CN":"大型橱柜"}`），**严禁原样渲染整串 JSON**
- 一律 `i18nText(value)` 按当前语言取值（优先当前语言，缺该语言回退另一语言）；非 JSON 串原样返回（无损），接口返回的字符串字段渲染前默认过一遍最稳
- 页面不得各自实现 JSON 解析（历史教训：warehouse-dashboard 首版本地实现漏了语言跟随，已统一收口 app.js）
- 注意：翻译列字段名不固定出现在哪些表（`product_template.name` / `product_category.name` 已确认；`stock_location.complete_name` 等为普通文本），**新表字段先用 dbx 看真实值形态**再决定是否过 `i18nText`

## 3. 语言切换交互（外壳）

- header 右侧 globe 下拉（**basecoat dropdown-menu 标记**，复用外壳 `buildDropdown`），位于主题切换左侧
- 选项式：`中文` / `English`，当前语言项 `✓` 前缀 + `role="menuitemradio"` + `aria-checked`
- 点击选项：写 `langMode` → toast（已切换为…）→ 350ms 后整页刷新；页面不得自实现语言切换入口或另存语言状态

## 4. key 约定

扁平点分命名空间：`shell.*`（外壳通用）、`menu.<MENU key>`（菜单项，key 与 `layout.js` MENU 一致）、`page.<页面>.*`（页面自有）、字典枚举用 `page.<页面>.state.<枚举>`。英文文案避免过长（按钮/标签空间有限）。

## 5. 验证口径

playwright 实测（本项目有过「DOM 对、视觉错」事故，交互改动必须实测）：

1. 语言下拉在主题切换左侧（比较 bounding rect x）；点开出现两个选项，当前项带 `✓`
2. 切换后整页刷新：`localStorage.langMode`、`document.documentElement.lang` 同步；菜单/KPI 标签/图表图例/翻译列内容随语言变化；`data-i18n` 节点无残留中文（英文态下）
3. 切回中文往返无损；en_US.json 临时删一个 key → 对应位置回退中文（回退机制生效）
4. 断网/404 `locales/` → 外壳仍全中文可渲染（fail-open）
