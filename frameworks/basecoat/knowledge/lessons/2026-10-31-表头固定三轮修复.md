# 表头固定三轮修复：sticky 弃用，双表模式定稿

## 场景

公司管理列表页要求「表头稳定固定、滚动条只在表头下方内容区域」，PM 连续两轮验收打回：表头随滚动震动、滚动条贯穿表头。

## 踩坑

第一轮用 `thead th{position:sticky}`，而 basecoat-lyra preflight 对 table 默认 `border-collapse:collapse`——合并边框模式下 sticky 单元格重绘错位，表头「先随滚再弹回」；改 `border-collapse:separate` 后真机断言 top 恒定 0px 抖动，PM 仍不满意——sticky 方案的滚动条天然贯穿表头高度，与「滚动条只在表头下方」的产品预期根本不匹配。第二轮双表架构又踩 CSS 规范陷阱：外层壳只写 `overflow-x:auto` 时另一轴 `visible` 被规范**强制升格为 auto**，壳意外成为纵向滚动者（子内容 979px 装在 563px 壳里），滚动条贯穿表头、表头带跟着滚。

## 修正

定稿双表模式：表头带（.pg-head-row + fixed 布局表）作为 `flex:none` 静态带放在滚动容器**外**；`.pg-vscroll`（flex:1 + min-height:0）是唯一纵向滚动者；横向滚动壳必须显式 `overflow-y:hidden`；两表列对齐靠 `table-layout:fixed` + 同一份 JS 列配置生成的 `<colgroup>`。真机断言：表头 top 精确恒定、滚动条只在表头下方、外壳 scrollTop 恒 0。

## 应用规则

表格表头钉死一律用「表头带脱离滚动容器」的双表模式，禁用 sticky 表头；纵向分层壳必须显式写全 `overflow-x` 与 `overflow-y` 两个轴（只写单轴会触发 visible→auto 升格）；验收必须含真机滚动采样断言 + 截图，不能只看 DOM。
